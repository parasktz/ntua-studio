# NTUA STUDIO — Κρατήσεις βιντεοσκόπησης

Σελίδα κρατήσεων με ημερολόγιο και slots πραγματικού χρόνου. Ο επισκέπτης βλέπει ποια slots είναι ελεύθερα, επιλέγει ένα ή περισσότερα, και τα κλείνει με **μία** υποβολή. Οι κρατήσεις αποθηκεύονται στο Firebase και η σελίδα φιλοξενείται δωρεάν στο GitHub Pages.

Αρχεία:

| Αρχείο | Ρόλος |
|---|---|
| `index.html` | Η σελίδα κρατήσεων (αυτή που μοιράζεσαι) |
| `admin.html` | Λίστα κρατήσεων + εξαγωγή CSV + κλείδωμα μη διαθέσιμων slots |
| `calendar.html` | Μηνιαίο ημερολόγιο με όλες τις δεσμευμένες ημέρες και ώρες |
| `config.json` | Όλες οι ρυθμίσεις — ημερομηνίες, ώρες, slots, Firebase |

---

## Βήμα 1 — Firebase (5 λεπτά)

1. Πήγαινε στο [console.firebase.google.com](https://console.firebase.google.com) και πάτα **Add project**. Δώσε ένα όνομα (π.χ. `ntua-studio`), το Google Analytics δεν χρειάζεται.
2. Από το μενού αριστερά: **Build → Realtime Database → Create Database**. Επίλεξε τοποθεσία `europe-west1` και ξεκίνα σε **locked mode**.
3. Στην καρτέλα **Rules** επικόλλησε τα παρακάτω και πάτα **Publish**:

```json
{
  "rules": {
    "bookings": {
      ".read": true,
      "$date": {
        "$slot": {
          ".write": "(!data.exists() && newData.exists()) || (data.exists() && !newData.exists() && data.child('ts').val() - now > 172800000)",
          ".validate": "newData.hasChildren(['name', 'start', 'code', 'ts']) && newData.child('ts').val() > now"
        }
      }
    }
  }
}
```

Τι επιτρέπουν οι κανόνες: ο καθένας μπορεί να **δημιουργήσει** κράτηση σε ελεύθερο slot, και μια κράτηση μπορεί να **ακυρωθεί** μόνο όσο απομένουν πάνω από 2 μέρες μέχρι την ώρα έναρξής της (το `172800000` είναι 2 μέρες σε χιλιοστά του δευτερολέπτου — αν αλλάξεις το `editDaysBefore` στο config, άλλαξε κι εδώ τον αριθμό σε *μέρες × 86400000*). Καμία κράτηση δεν μπορεί να τροποποιηθεί επί τόπου — «αλλαγή» σημαίνει ακύρωση και νέα κράτηση. Εσύ, ως διαχειριστής, σβήνεις οτιδήποτε ανά πάσα στιγμή από την κονσόλα του Firebase (Realtime Database → `bookings` → πατάς το ✕ στο slot).

**Πώς αλλάζει ο χρήστης την κράτησή του:** με την υποβολή, η σελίδα του δίνει έναν κωδικό διαχείρισης (π.χ. `K7F3-Q9ZM`) — έναν για όλα τα slots της υποβολής. Στο τμήμα «Έχεις ήδη κράτηση;» στο κάτω μέρος της σελίδας, βάζει τον κωδικό, βλέπει τα επερχόμενα slots του και ακυρώνει όποιο θέλει· μετά κλείνει νέο κανονικά. Slots που απέχουν λιγότερο από 2 μέρες εμφανίζονται κλειδωμένα, και το όριο ελέγχεται και από τους κανόνες του Firebase, όχι μόνο από τη σελίδα. Αν κάποιος χάσει τον κωδικό του, μπορείς να τον βρεις στην κονσόλα του Firebase, μέσα στην εγγραφή του slot (πεδίο `code`).

Μια ειλικρινής σημείωση για την ασφάλεια: χωρίς λογαριασμούς χρηστών (Firebase Auth), ο κωδικός προστατεύει από λάθη και απλή κακή χρήση — κάποιος με τεχνικές γνώσεις που θα διαβάσει απευθείας τη βάση θα μπορούσε να δει κωδικούς άλλων. Για κρατήσεις studio σε πανεπιστημιακό περιβάλλον αυτό συνήθως αρκεί· αν ποτέ χρειαστείς αυστηρότερη προστασία, το επόμενο βήμα είναι σύνδεση χρηστών με Firebase Authentication.

4. Πήγαινε **Project settings** (γρανάζι πάνω αριστερά) → κάτω στο **Your apps** → πάτα το εικονίδιο **`</>`** (Web) → δώσε ένα ψευδώνυμο → **Register app**. Θα σου εμφανίσει ένα μπλοκ `firebaseConfig` με τιμές όπως `apiKey`, `projectId` κ.λπ.
5. Άνοιξε το `config.json` και αντέγραψε αυτές τις τιμές στο τμήμα `"firebase"`. Πρόσεξε ιδιαίτερα το `databaseURL` — αν δεν εμφανίζεται στο μπλοκ, θα το βρεις στη σελίδα του Realtime Database (η διεύθυνση πάνω από τα δεδομένα, π.χ. `https://ntua-studio-default-rtdb.europe-west1.firebasedatabase.app`).

Σημείωση: τα στοιχεία αυτά δεν είναι «μυστικά» — είναι σχεδιασμένα να μπαίνουν σε δημόσιες σελίδες. Την προστασία την κάνουν οι κανόνες του βήματος 3.

## Βήμα 2 — GitHub Pages

1. Φτιάξε νέο repository στο GitHub (π.χ. `studio-booking`) και ανέβασε τα 5 αρχεία (**Add file → Upload files**).
2. **Settings → Pages → Source: Deploy from a branch → Branch: main / (root) → Save**.
3. Σε 1–2 λεπτά η σελίδα θα είναι διαθέσιμη στο `https://ΤΟ-USERNAME-ΣΟΥ.github.io/studio-booking/`. Το ημερολόγιο κρατήσεων βρίσκεται στο `.../studio-booking/calendar.html` και η λίστα διαχείρισης στο `.../studio-booking/admin.html`.

Σημείωση: το `index.html` δεν δουλεύει αν το ανοίξεις απευθείας ως αρχείο από τον υπολογιστή (file://), γιατί ο browser μπλοκάρει τη φόρτωση του `config.json`. Δοκίμαζέ το στο GitHub Pages ή με τοπικό server (`python -m http.server`).

## Βήμα 3 — Προσαρμογή στο config.json

Εδώ είναι όλη η ευελιξία — καμία αλλαγή δεν χρειάζεται στον κώδικα:

| Ρύθμιση | Τι κάνει | Παράδειγμα |
|---|---|---|
| `dateRange` | Περίοδος κρατήσεων | `{"start": "2026-10-01", "end": "2026-12-10"}` |
| `openWeekdays` | Ανοιχτές ημέρες: 1=Δευτέρα … 7=Κυριακή | `[1, 2, 3, 4, 5]` |
| `excludedDates` | Αργίες / κλειστές ημέρες | `["2026-10-28", "2026-11-17"]` |
| `hours` | Ωράριο λειτουργίας | `{"start": "09:00", "end": "17:00"}` |
| `slotMinutes` | Διάρκεια κάθε slot σε λεπτά | `60`, `30`, `90`… |
| `maxSlotsPerBooking` | Μέγιστα slots ανά υποβολή | `3` |
| `editDaysBefore` | Έως πόσες μέρες πριν επιτρέπεται ακύρωση/αλλαγή (άλλαξε και τον αριθμό στους κανόνες: μέρες × 86400000) | `2` |
| `dateOverrides` | Ειδικό ωράριο/διάρκεια για συγκεκριμένη ημέρα | δες παρακάτω |
| `fields` | Αν το email/τηλέφωνο εμφανίζεται ή είναι υποχρεωτικό | `{"email": {"show": true, "required": true}}` |

Το `dateOverrides` καλύπτει τις εξαιρέσεις χωρίς να πειράξεις το γενικό ωράριο:

```json
"dateOverrides": {
  "2026-10-15": { "start": "10:00", "end": "14:00" },
  "2026-11-20": { "slotMinutes": 30 },
  "2026-12-04": { "closed": true }
}
```

Παλιότερες ημερομηνίες από τη σημερινή απενεργοποιούνται αυτόματα, οπότε δεν χρειάζεται συντήρηση καθώς περνούν οι μέρες.

## Μη διαθεσιμότητα studio (διαχειριστής)

Στην κορυφή του `admin.html` υπάρχει το πάνελ «Μη διαθεσιμότητα studio»: διαλέγεις ημερομηνία, βλέπεις τα slots της, πατάς όσα θέλεις να κλειδώσεις (ή «Όλα τα ελεύθερα» για ολόκληρη τη μέρα) και πατάς «Αποκλεισμός». Οι επισκέπτες θα τα βλέπουν ως **✕ Μη διαθέσιμο** — διαφορετικά από τα «Κατειλημμένα» — και δεν θα μπορούν να τα κλείσουν. Το κλείδωμα γίνεται με transaction, οπότε δεν πατάει ποτέ κράτηση που έγινε το ίδιο δευτερόλεπτο. Για άρση, πατάς το κλειδωμένο slot (✕) στο ίδιο πάνελ· αν απομένουν λιγότερες μέρες από το όριο του `editDaysBefore`, οι κανόνες δεν επιτρέπουν πλέον διαγραφή από τη σελίδα και η άρση γίνεται από την κονσόλα του Firebase.

Σημείωση: το `admin.html` δεν έχει κωδικό πρόσβασης — όποιος έχει το link του μπορεί να κλειδώνει slots. Αυτό δεν προσθέτει νέο ρίσκο σε σχέση με τα υπάρχοντα (οποιοσδήποτε μπορεί έτσι κι αλλιώς να «κλείσει» slots από τη δημόσια φόρμα), αλλά καλό είναι να μοιράζεσαι το link της σελίδας διαχείρισης μόνο με την ομάδα του studio.

## Πώς αποφεύγεται το διπλοκλείσιμο

Κάθε slot γράφεται στη βάση με *transaction*: η εγγραφή γίνεται **μόνο αν το slot είναι ακόμα κενό** εκείνη τη στιγμή. Αν δύο άτομα πατήσουν «Κράτηση» ταυτόχρονα για το ίδιο slot, μόνο ο ένας θα το πάρει — ο άλλος θα δει μήνυμα ότι το slot μόλις κλείστηκε και θα του ζητηθεί να διαλέξει άλλο. Επιπλέον, η διαθεσιμότητα ενημερώνεται ζωντανά: αν κάποιος κλείσει ένα slot όσο έχεις ανοιχτή τη σελίδα, θα το δεις να γκριζάρει χωρίς refresh.
